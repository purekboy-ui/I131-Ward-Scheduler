# System Workflow and Rules

## 1. 系統目標

這個原型主要是把 I-131 排程工作拆成三件事：

1. **先卡位**
2. **再補齊資料**
3. **由管理者收單確認後鎖定**

## 2. 住院大劑量 SOP

1. 一般使用者從月曆選擇日期與床位。
2. 建立時可先只填部分資料，但預約狀態固定為 `待確認`。
3. 一般使用者只可修改自己建立、且尚未被鎖定的預約。
4. 管理者核對完整資料後執行收單。
5. 收單後狀態改為 `已確認`。
6. `已確認` 後，一般使用者不可再編輯、刪除、移動。

## 3. 門診小劑量 SOP

1. 門診小劑量不占住院床位。
2. 預設允許任何未來日期預約。
3. 建立時同樣固定為 `待確認`。
4. 管理者核對後再收單。
5. 收單後，一般使用者不可再修改。

## 4. 管理者 SOP

管理者需要能做三種事：

1. **收單確認**
2. **管理床位開關**
3. **維護主治醫師與帳號**

### 4.1 收單前必填欄位

若缺少下列任一欄位，不可改成 `已確認`：

- 病歷號
- 病人姓名
- 劑量
- 主治醫師

### 4.2 床位管理

- 以 `日期 x 床位` 控制是否開床
- 後台可直接切換 5B / 6B
- 月曆日管理視窗與後台共用同一套 `dateOverrides` 資料

## 5. 權限矩陣

| 功能 | manager | super_editor | editor | viewer |
| --- | --- | --- | --- | --- |
| 查看月曆 | Yes | Yes | Yes | Yes |
| 新增住院預約 | Yes | Yes | Yes | No |
| 新增門診小劑量 | Yes | Yes | Yes | No |
| 編輯自己的待確認預約 | Yes | Yes | Yes | No |
| 編輯他人預約 | Yes | 視後續實作 | No | No |
| 收單確認 | Yes | No | No | No |
| 後台管理 | Yes | No | No | No |
| 查看操作紀錄 | Yes | Yes | Yes | No |

> `super_editor` 目前是保留角色；實際上線時請依院內需求再細化。

## 6. 月曆顯示規則

### 6.1 住院月曆

每個日期固定顯示 5B 與 6B 的狀態之一：

- 已排病人
- 可直接新增
- 未開床

優先呈現資訊：

1. 床位
2. 病人
3. 劑量
4. 狀態

### 6.2 門診月曆

- 同日顯示至少 3 筆門診資訊
- 超出時以摘要方式呈現
- 一樣保留快速新增入口

## 7. 預約管理頁規則

設計目的是讓人員快速核對，而不是做裝飾性展示，所以重點欄位固定為：

- 狀態
- 日期
- 排程位置
- 病歷號 / 病人姓名
- 劑量 / 訂藥
- 主治醫師

## 8. 訂藥管理頁規則

訂藥管理專注在核對：

- 病人
- 日期
- 床位
- 劑量
- 劑型
- Thyrogen
- 是否已訂藥

目的是降低訂藥時對錯人的風險。

## 9. 醫師主檔同步規則

主治醫師清單不只在後台顯示，也會同步影響：

- 住院預約表單
- 門診預約表單
- 報表篩選

系統也會從既有預約補齊醫師主檔，避免下拉選單與資料不一致。

## 10. 目前不是正式版的部分

以下都還是原型層級：

- 前端 mock login
- 前端 mock data
- 前端 audit log
- 前端報表匯出
- 沒有正式 API / DB
- 沒有正式資安機制
